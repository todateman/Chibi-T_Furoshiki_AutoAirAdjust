  • PULSE_WIDTH_MIN_MS を 8 → 4 に変更。 指令4msは、開始圧0.07〜0.29MPaの5ショットすべてで動作した。動作の境目（実測開弁 3.28〜3.65ms）に対し 0.35ms 以上の余裕がある。3.6ms 以下は境目に近く、開始圧や電圧で動作しなくなり得るため採らない。
  • PULSE_COOLDOWN_MS（50）は据え置き。 整定時間の最大 34ms（8ms・開始圧0付近）に対し余裕がある。ファームの2次側読み値は、パルス後 約200ms の時点ですでに整定値に達していた。
  • PULSE_WIDTH_MAX_MS / GROW / SHRINK / MAX_REGULATION_EPISODE_MS は変更しない。8ms を超える幅の特性は未測定で、変更の根拠がない。
  • 4ms の1パルスでも ΔP が目標帯の幅を超える。 幅の調整で 0.02MPa 台を狙うと、3.3〜3.65ms の急峻な立ち上がり（約 0.13MPa/ms）に当たり、現状の閉弁精度では制御できない。目標帯 ±0.01MPa への収束には、下流容積の追加（バッファチャンバー）や閉弁精度の改善が別途必要。

測定方法

測定専用ビルド（env:m5stack-core2-characterize、-DCHARACTERIZE_MODE）で、自動パルスを止め、Serial から P<ms> / U<us> で単発パルスを指令した。指令幅の範囲は 1〜8ms。閉弁は通常ビルドと同じ ValveDriver の esp_timer で行う。

  • トリガー: CH1 立ち下がり（ローサイドスイッチのため LOW = 開弁、平常時 約15V）、レベル 7.8V、単発。CH1 が半分（約7.5V）を下回る区間の長さを「実測の開弁時間」とした。
  • 開始圧の作り方: 下流の圧力は数秒〜十数秒で抜けるため、運用点付近（0.23〜0.33MPa）から測るときは、先に 8ms パルスを2発打って圧力を上げ、その直後にオシロをアームして本番の1発だけを撮った。開始圧はショットごとにオシロのベースライン値を記録した。
  • 圧力換算: MPX5700AP の公称特性（Vs=5V）で、kPa = (V − 0.2) / (4.5/700)、ゲージ = 絶対 − 101.3kPa。オシロ値とファーム読み値は絶対値で約 0.016MPa ずれるが、ΔP は一致する（8ms・開始圧0付近で ファーム +0.148 / オシロ +0.1495MPa）。
  • デッドタイム: CH1 の開弁エッジから、CH2（0.1ms平均）がベースライン + max(10mV, 8σ) を超えるまで。ΔP（正味）: 取得窓末尾10msの平均 − 開弁前ベースライン。整定時間: 閉弁後、最終値から ±0.01MPa（および ±10%）の帯を最後に外れた時刻 − 閉弁時刻。
  • NORMAL取得は使わない: 1000点（50µs間隔）ではリンギングが折り返して見えるため、RAW 1M点（80〜160ns間隔）を取得した。

1パルスの ΔP と開弁幅

横軸はオシロで測った実測の開弁時間、縦軸は開弁前後の正味 ΔP。実測開弁 3.28ms（3.2ms 指令）では圧力が動かず、3.5〜3.65ms の間で 0 から約 0.047MPa に立ち上がる。4ms を超えると増え方は緩やかになる。

閉弁のばらつきと、8ms パルスの開始圧依存

指令幅に対する開弁時間の増加分

標準は +0.08ms（開弁・閉弁エッジのスイッチング遅れ）。それを超えて遅れるショットがあり、原因は esp_timer タスクの実行遅延と推測している（未確認）。動作の境目付近では、この遅れがそのまま ΔP のずれになる。

8ms パルスの ΔP と開始圧

同じ 8ms でも、開始圧が高いほど差圧が小さくなり ΔP は減る（0MPa付近 +0.15 → 0.33MPa 付近 +0.096MPa）。運用点でも 8ms では目標帯の幅 0.02MPa の約5倍上がる。

未解決事項と次のステップ

  • 閉ループ検証が未実施。 更新した config.h を量産ビルドに書き込み、運用構成で目標帯 0.34〜0.36MPa への収束・オーバーシュート・REGULATION TIMEOUT の有無を確認する。
  • 閉弁のばらつきの改善。 esp_timer の代わりにハードウェアタイマー割り込み（GPTimer ISR）で閉弁することで、+0.1〜0.9ms の遅れを抑えられる可能性がある。
  • ΔP が目標帯の幅を超える問題。 4ms でも +0.055〜0.064MPa。バッファチャンバーによる下流容積の追加（ΔP ∝ 1/V）などのハード対策が必要。
  • 8ms を超える幅の特性は未測定。 PULSE_WIDTH_MAX_MS / GROW の見直しにはこの範囲の測定が要る。
  • スピードコントローラの有無・絞り位置の記録。 次回以降の測定条件として記録する。
  • 生波形（1M点 × 27ショット、約52MB）はリポジトリに含めていない。取得・解析スクリプトは tools/（run_shot.sh, scope_capture.py, analyze_pulse.py, send_pulse.py）。
